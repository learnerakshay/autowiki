# Landing surface

Mode: Persuade

Audience: Developers seeing AutoWiki for the first time, including a college project demonstration audience.

Job: Understand within seconds that AutoWiki turns a public GitHub repository into a structured technical wiki, see authentic product proof, and open the operational workspace.

Primary action: Open `/workspace` to generate a wiki.

Proof: Verified `octocat/Spoon-Knife` output, including real chapter names, descriptions, repository paths, and Mermaid relationships.

Constraints: Preserve the Prompt 02 Clean Light system, existing routes and API behavior, Wiki Mermaid lifecycle, factual copy, reduced motion, and mobile usability. No fabricated metrics, testimonials, repositories, or future features.

## Direction contract

THESIS: AutoWiki is shown as a repository becoming a readable technical document, not as another chat box. The page refuses the centered headline above a row of interchangeable feature cards; the generated reader is present as proof in the first viewport.

OWN-WORLD: The established Clean Light palette carries a precise documentation-studio language: white reading surfaces, cool canvas, crisp rules, restrained indigo, editorial type scale, repository paths, chapter rails, and diagram connectors. Corners remain 8–12px and shadows stay quiet.

STORY: Visitors first see the source-to-wiki promise and authentic output, then learn the three-stage pipeline, compare the flagship chapter and diagram capabilities with supporting grounded chat, inspect the real generation architecture, and open Workspace.

FIRST VIEWPORT: A restrained sticky header sits above an asymmetric split hero. A 68px-scale headline and two actions occupy the left; a large interactive documentation reader using verified Spoon-Knife output occupies the right and remains substantially visible without scrolling. On mobile, proof follows the actions as a purpose-built stacked reader.

FORM: Code-led, surface extension inside the established Clean Light world. Signature interaction: keyboard-operable chapter switching changes the authentic chapter proof while a single short GSAP entrance introduces copy and reader together. Seed key: brief-pinned-prompt-03.

## Prompt 11 consolidation

The landing page is the Persuade-mode opening of the connected journey `repository → planned chapters → navigable technical wiki`. Bright white and cyan-tinted surfaces, deep navy display type, and the literal Repository / Chapters / Wiki sequence make that mechanism legible before feature detail. The verified Spoon-Knife reader remains first-viewport proof, while `Explore Sample Wiki` opens `/wiki/sample/spoon-knife` so evaluators can inspect the shared production reader without starting backend or provider work.

Desktop keeps the asymmetric copy/proof composition; 900px stacks it, 760px converts feature/pipeline structures, 520px creates full-width actions and an adaptive horizontal chapter preview, and 320px remains overflow-safe. GSAP is limited to the first-view hierarchy, one-time section reveals, and chapter continuity; reduced-motion users receive the complete static composition immediately.

FINISH: Prompt 11 final reviewer disposition is SHIP. The landing proof, sample entry point, responsive reflow, reduced-motion state, and honest route behavior are documented and verified.
